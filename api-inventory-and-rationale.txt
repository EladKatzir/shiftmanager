EXECUTIVE SUMMARY
-----------------
This document catalogs a comprehensive, additive REST API layer designed for external third-party integrations with the ShiftManager application. The current system has NO existing APIs—it is a pure Razor Pages application. All proposed APIs are strictly additive and use wrapper/facade patterns to avoid modifying existing business logic or UI flows.

The API design prioritizes:
- Read-only access for safety (90% of endpoints are GET)
- Multi-tenant isolation via API keys scoped to CompanyId
- Feature flags for gradual rollout (all default to OFF)
- RFC-7807 error schemas for standardization
- Rate limiting (100 req/min default, 429 + Retry-After)
- Comprehensive audit logging

DOMAIN COVERAGE
----------------
1. Users (CRUD + Profile management)
2. Shifts (Schedule viewing, assignment querying)
3. Time-Off Requests (Submit, approve, query)
4. Swap Requests (Create, approve, query)
5. Chores (Assign, cancel, query)
6. Notifications (Query, mark read, send)
7. Analytics (Reporting, metrics, insights)
8. Audit Logs (Compliance, security audit)
9. Webhooks (Event subscriptions)

INFRASTRUCTURE REQUIREMENTS (Sidecar/Additive Only)
----------------------------------------------------
- New table: ApiKeys (Id, Key, CompanyId, Scopes, IsActive, RateLimit, CreatedAt, ExpiresAt)
- New table: ApiWebhooks (Id, CompanyId, Url, Secret, Events, IsActive, CreatedAt)
- New table: ApiRequestLogs (Id, ApiKeyId, Endpoint, Method, StatusCode, Timestamp, Duration)

- New config: Features:ApiEnabled, Features:WebhooksEnabled
