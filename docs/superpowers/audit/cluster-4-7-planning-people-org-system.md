## MAIN-LOOP VERIFIED

### C4-F01 (CRITICAL) — bulk CSV import mints privileged accounts; the guard checks the wrong axis

`Pages/Admin/Users.cshtml.cs` (bulk import, ~:3299):

```csharp
importTemplate = await _roleService.GetRoleTemplateByKeyAsync(roleStr);   // from the CSV string
if (importTemplate != null) { role = importTemplate.DerivedUserRole ?? UserRole.Employee; }
...
// Don't allow bulk creation of Owner/Director/AreaAdmin
if (role == UserRole.Owner || role == UserRole.Director || role == UserRole.AreaAdmin)
{ role = UserRole.Employee; importTemplate = await _roleService.GetRoleTemplateByKeyAsync("Employee"); }
...
var user = new AppUser { ..., Role = role, RoleTemplateId = importTemplate?.Id, ... };
```

The blocklist tests the **legacy `UserRole` enum**, but authorization in this app is driven by
**`RoleTemplateId`**, which is resolved from the CSV string and assigned regardless.

Verified against the seeded DB — the blocklist stops only 3 of 10 templates:

| Template | Auto-grants | `DerivedUserRole` | Blocklist |
|---|---|---|---|
| **MoleculeAdmin** | **102** | Manager (1) | **passes** |
| **BRDirector** | **71** | Manager (1) | **passes** |
| **Lead** | 58 | Manager (1) | **passes** |
| **Assigner** | 27 | Assigner (5) | **passes** |
| DepartmentLead / Employee / Trainee | — | 1 / 2 / 4 | passes |
| Owner / Director / AreaAdmin | — | 0 / 3 / 6 | blocked |

**Failure scenario.** A caller who can use bulk import uploads one CSV row
`me@x.test,Backdoor,Passw0rd!,MoleculeAdmin`. The account is created with `RoleTemplateId = 7` and
MoleculeAdmin's 102 molecule-wide auto-grants. The importer chose the password, so they can log in
as it immediately (`MustChangePassword = true` does not prevent that first login).

**Root cause is drift, not omission.** The blocklist was correct when roles WERE the authorization
model. The app migrated to grant-based auth via RoleTemplates and this guard was never migrated with
it — it still faithfully checks the axis that no longer decides anything.

**Proposed fix:** blocklist by **template**, not derived role — reject any `roleStr` resolving to a
template the caller could not assign directly (reuse `DirectorService.CanAssignRoleAsync` / the same
check the single-user create path uses), and cap the import at templates at or below the caller's
own privilege.
