Quick Info Widget Redesign — Approach Options

3 data sections: On-Call Hakam, On-Call Lead, Store Hours. Configurable per-molecule by admins.

A

Recommended: Organization Page + Widget Gear

Store management: New /Admin/Organization/Stores page — consistent with ChoreTypes, DutyTypes, etc. Molecule admins add stores, set hours per day (with break windows).

Widget config: Small gear icon on the Quick Info widget itself (visible only to molecule admins). Opens a compact settings panel/modal where the admin selects which on-call roles and which stores appear for their molecule.

Widget display: Redesigned to show 3 sections — Hakam, Lead (from OnDuty table), and Store Hours (from new Store model).

Pros

  • Follows existing /Admin/Organization/* pattern
  • Widget config is discoverable right where it's used
  • Minimal navigation for molecule admins

Cons

  • Gear icon on widget adds a new interaction pattern
B

Unified Admin Config Section

Store management + Widget config: Both as new sections on the existing /Admin/Config page. One section for managing stores & hours, another for widget display preferences.

Widget display: Same redesign — Hakam, Lead, Store Hours.

Pros

  • Everything in one place
  • No new pages needed

Cons

  • Admin/Config may become bloated
  • Stores are organizational entities, not config settings — conceptual mismatch
  • Widget config buried in settings, less discoverable
C

Area Detail Page Extension

Store management: Add a "Stores" tab to the Area detail/edit page under /Admin/Organization/Areas. Manage stores within the context of their parent area.

Widget config: Separate /Admin/WidgetConfig page — molecule admins pick what to show.

Pros

  • Stores shown in the context of their parent area
  • Natural hierarchy visualization

Cons

  • Areas page would need major refactoring to support tabs/detail view
  • Two separate pages for related config (stores + widget)
  • More complex navigation for admins
