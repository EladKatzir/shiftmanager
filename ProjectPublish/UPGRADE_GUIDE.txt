SCENARIO 1: UPGRADING FROM RUNNING APPLICATION
================================================================================

If you're currently running ShiftManager via START_HERE.bat or console:

Step 1: Stop the Current Version
  - Close the console window (the black window showing application logs)
  - Or press Ctrl+C in the console
  - Wait for the application to fully stop (2-3 seconds)

Step 2: Verify Application Stopped
  - Open Task Manager (Ctrl+Shift+Esc)
  - Check that ShiftManager.exe is not running
  - If still running, kill the process

Step 3: Backup Your Data
  - Copy app.db to a safe location (e.g., Desktop or USB drive)
  - Copy app.db-shm and app.db-wal if they exist
  - Copy appsettings.json (contains your configuration)

Step 4: Backup Current Installation (Optional but Recommended)
  - Rename the ProjectPublish folder to ProjectPublish_OLD_[date]
  - Or copy the entire folder to another location

Step 5: Extract New Version
  - Extract ShiftManager-v2.8.2-win-x64.zip
  - Extract to the same location as the old version
  - Overwrite files when prompted

Step 6: Restore Configuration
  - Open the NEW appsettings.json
  - Copy your SEED_ADMIN_PASSWORD from the old appsettings.json
  - Copy any other custom settings you had changed
  - Save the file

Step 7: Restore Database
  - If you renamed the folder in Step 4, copy app.db back
  - Or if you copied the folder, copy app.db from the old folder
  - Place app.db in the new ProjectPublish folder

Step 8: Start New Version
  - Double-click START_HERE.bat
  - The new version will detect the existing database
  - Migrations will run automatically if needed
  - Wait for "Now listening on: http://localhost:5000"

Step 9: Verify Upgrade
  - Open http://localhost:5000 in your browser
  - Login with admin@local and your password
  - Check that your data is present (users, shifts, etc.)
  - Verify the version number in the footer

Step 10: Clean Up
  - If everything works, delete ProjectPublish_OLD_[date] folder
  - Keep your database backup for a few days just in case

SCENARIO 2: UPGRADING FROM WINDOWS SERVICE
================================================================================

If ShiftManager is running as a Windows Service:

Step 1: Stop the Service
  - Open Services (services.msc)
  - Find "ShiftManager" service

  - Wait for service to stop completely

  - Navigate to the service installation folder

Step 4: Restore Configuration
  - Open the NEW appsettings.json

  - Ensure SEED_ADMIN_PASSWORD is set
  - Save the file

Step 5: Start the Service
  - Open Services (services.msc)
  - Find "ShiftManager" service
  - Right-click â†’ Start
  - Check service status is "Running"

Step 6: Verify Upgrade
  - Open http://localhost:5000 (or your configured URL)
  - Login and verify everything works
  - Check the version number

Note: Service configuration is NOT overwritten during upgrade.

================================================================================
HANDLING UPGRADE CONFLICTS
================================================================================

Issue: START_HERE.bat reports "ShiftManager is already running"
Solution:
  - Let START_HERE.bat stop it automatically (choose [S])
  - Or manually kill the process in Task Manager
  - Wait 4 seconds for file locks to release
  - Try again

Issue: Port 5000 is in use
Solution:
  - Check that no other application is using port 5000
  - Use netstat -ano | findstr ":5000" to find the process
  - Stop the conflicting process or change ShiftManager port

Issue: Access denied / Cannot write files
Solution:
  - Run as Administrator
  - Or ensure your user account has write permissions to the folder

Issue: Database migration errors
Solution:
  - Check that app.db is not locked by another process
  - Verify app.db is not corrupted (restore from backup if needed)
  - Check application logs for specific error messages

================================================================================
DATABASE MIGRATIONS
================================================================================

ShiftManager automatically applies database migrations on startup.

What happens during upgrade:
  1. Application detects database version
  2. Compares with code version
  3. Applies pending migrations automatically
  4. Logs migration results

Migration Duration:
  - Usually instant (< 1 second)
  - May take longer for large databases

If migration fails:
  - Application will NOT start
  - Error will be logged
  - Restore database from backup
  - Contact support

ROLLBACK PROCEDURE
================================================================================

If the upgrade fails or causes issues:

Step 1: Stop New Version
  - Close application / stop service / stop IIS pool

Step 2: Restore Old Version
  - Delete or rename the new ProjectPublish folder
  - Restore from backup (ProjectPublish_OLD or your backup)

Step 3: Restore Database
  - Copy app.db from your backup
  - Overwrite the current app.db

Step 4: Start Old Version
  - Use the old START_HERE.bat or start service/IIS

Step 5: Verify Rollback
  - Login and check that everything is back to normal
