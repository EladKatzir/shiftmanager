## 1. Concepts & Terminology

- **Roster Grid**: Calendar-style grid where columns are dates (with "date" and "day of week" headers) and rows represent individual shifts.
- **Shift Row**: A horizontal row displaying shift metadata and a cell for each date.
- **Shift Cell**: Intersection of shift row and date column; contains assignment slots.
- **Assignment Slot**: Sub-cell within a shift cell, holding one Primary User and optionally a Trainee.
- **Users DDL**: Dropdown list to pick a user for a slot.
- **Context Menu (per slot)**: Offers actions—Add Trainee, Change Primary User, Remove User.
- **Add Assignment**: Control inside an empty cell (or a “+” icon at the row's left) that triggers the amount picker.

---

## 2. User Flow

### 2.1 Create or Edit a Shift Row
- Left side of each shift row must include: **Shift Type** (enum), **Shift Name** (free text), and **Shift Hours** (time range).
- A large “+” control at the far left adds a new shift row with default metadata.

### 2.2 Add Assignments to a Cell
- User clicks “Add Assignment” in an empty cell.
- Modal/popup displays an amount-picker UI: plus/minus buttons flank a numeric counter (min 1, max configurable), labeled "Number of people needed". Actions: Create Shift (primary), Cancel (secondary).
- On Create Shift, the cell splits into *N* assignment slots (based on chosen number). Each slot displays a users DDL (unset).
- Slots stack vertically.

### 2.3 Populate a Slot
- Selecting from the DDL sets a Primary User for the slot. The slot label shows the display name (e.g., "Alex Johnson").
- Clicking the slot label or the "…" icon brings up the context menu:
   - **Add Trainee**: Opens another DDL; label updates: Primary User, Trainee (comma-separated).
   - **Change Primary User**: Reopens DDL; tries to preserve trainee if valid.
   - **Remove User**: Clears slot (back to DDL state). If all slots in a cell are empty, the “Add Assignment” control returns.

---

## 3. UX Details & States

### 3.1 Cell States
- *Empty*: Shows "Add Assignment" control.
- *Configured*: Contains N slots—each can be:
   - Unassigned (DDL visible)
   - Assigned (shows primary user, optional trainee)
   - Assigned + Trainee (Primary, comma, Trainee)

### 3.2 Visual Details
- Column headers: Date on first row, day of week on second.
- Assignment slots: Render as horizontal pills/bars inside cells.
- Trainee: Comma-separated after primary user (e.g., "Maria, John (trainee)").

### 3.3 Interactions
- **Keyboard**: Arrow keys move cell focus. Enter on an empty cell opens amount picker; Enter on slot opens DDL/context menu.
- **ARIA**: Each slot must be focusable (button or div) with `aria-haspopup="menu"`. Context menus: `role="menu"`, each action: `role="menuitem"`.

---

## 4. Validation & Business Rules

- No user may be assigned to overlapping shifts or the same timeslot (if enabled); block and show error inline or via toast.
- Maximum 1 trainee per slot.
- Changing Primary User: Keep assigned trainee if valid, or prompt for removal.
- Resizing (changing number of slots, N):
   - Increasing N: add new empty slots.
   - Decreasing N: require confirmation if removals impact assigned users.
- Removing a slot's user (if trainee assigned) removes both; slot becomes empty.
- DDL options must exclude users already picked in the same cell; (optional) filter by role/certification/capacity/availability.

## Output Format

### 1. UI State / ARIA Structure
- Every assignment slot should use its unique slot id and have ARIA attributes:
  ```html
  <div role="button" tabindex="0" aria-haspopup="menu" id="slot-SLOT_ID">
    ...
  </div>
  ```
- Context menu:
  ```html
  <div role="menu">
    <button role="menuitem">Add Trainee</button>
    <button role="menuitem">Change Primary User</button>
    <button role="menuitem">Remove User</button>
  </div>
  ```
