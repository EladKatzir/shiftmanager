================================================================================

  1. Open "appsettings.json" in Notepad
  2. Find: "SEED_ADMIN_PASSWORD": "",
  3. Change to: "SEED_ADMIN_PASSWORD": "YourStrongPassword123!",
  4. Save and close

  - Double-click: START_HERE.bat
  - Wait for "Now listening on: http://localhost:5000"

STEP 3: Login
  - Open browser: http://localhost:5000
  - Login: admin@local / [your password from Step 1]
  - Done!

Time Required: 2 minutes

================================================================================

For production use without Windows Service:

  1. Copy ShiftManager-v3.9.85-win-x64.zip to target server
  2. Extract to installation folder (e.g., C:\ShiftManager)
  3. Verify 525 files extracted

  1. Open appsettings.json

  4. Save and close

  - Run: ShiftManager.exe

Step 4: Verify Deployment
  - Open: http://localhost:5000
  - Login: admin@local / [your password]

  - Check: Can create test shift
  - Check: OFFLINE shift type is available

  - To stop: Close window or press Ctrl+C

Limitations:

SECTION 4.3: IIS HOSTING DEPLOYMENT
================================================================================

For enterprise deployments with IIS:

Prerequisites:
  - IIS installed
  - ASP.NET Core Hosting Bundle 8.0
  - URL Rewrite Module (optional)

Installation Steps:
  1. Extract package to IIS application folder (e.g., C:\inetpub\ShiftManager)
  2. Configure appsettings.json
  3. Create IIS Application Pool:
     - Name: ShiftManager
     - .NET CLR Version: No Managed Code
     - Managed Pipeline: Integrated
  4. Create IIS Site or Application:
     - Physical Path: C:\inetpub\ShiftManager
     - Application Pool: ShiftManager
     - Bindings: http://*:5000
  5. Set Permissions:
     - Grant IIS_IUSRS read access to application folder
     - Grant IIS_IUSRS write access for database
  6. Start site in IIS Manager
  7. Verify: Open http://localhost:5000

Benefits of IIS:
  - Automatic process management
  - Advanced monitoring and logging
  - Load balancing support
  - Integration with Windows Authentication (if needed)

SECTION 6: NETWORK ACCESS SETUP
================================================================================

By default, ShiftManager only accepts connections from localhost.

To enable network access:

Step 1: Update Configuration
  1. Open appsettings.json
  2. Find Kestrel:Endpoints:Http:Url
  3. Change from: "http://localhost:5000"
  4. Change to: "http://*:5000"
  5. Save and close

Step 2: Configure Windows Firewall
  â€¢ Open: Windows Defender Firewall with Advanced Security
  â€¢ Create Inbound Rule:
    - Rule Type: Port
    - Protocol: TCP
    - Port: 5000
    - Action: Allow
    - Profile: Domain, Private (as needed)
    - Name: ShiftManager HTTP
    - Description: Allow HTTP access to ShiftManager

  Command line:
  netsh advfirewall firewall add rule name="ShiftManager HTTP" dir=in action=allow protocol=TCP localport=5000

Step 3: Restart Application
  - Stop ShiftManager (close console or stop service)
  - Start ShiftManager again
  - Application now accepts network connections

Step 4: Verify Network Access
  - From another computer on the network:
  - Open: http://[server-ip]:5000
  - Example: http://192.168.1.100:5000
  - Should see ShiftManager login page

Security Note:
  - Network access uses HTTP (not encrypted)
  - For production, configure HTTPS (see Section 9.2)
  - Consider using VPN for remote access
  - Keep Windows Firewall enabled

SECTION 7: WINDOWS SERVICE INSTALLATION
================================================================================

For production deployments, run as Windows Service:

Method 1: Using NSSM (Recommended)

Download NSSM (Non-Sucking Service Manager):
  - Available at: nssm.cc
  - Transfer to server via USB if air-gapped

Installation Steps:
  1. Extract nssm.exe to C:\ShiftManager\
  2. Open Command Prompt as Administrator
  3. Run: nssm install ShiftManager
  4. GUI opens - configure:
     - Path: C:\ShiftManager\ShiftManager.exe
     - Startup directory: C:\ShiftManager
     - Service name: ShiftManager
  5. Click Install service
  6. Start service: nssm start ShiftManager

Service Configuration:
  â€¢ Startup type: Automatic
  â€¢ Recovery: Restart on failure
  â€¢ Log on: Local System (or dedicated service account)

Commands:
  nssm install ShiftManager     # Install service
  nssm start ShiftManager       # Start service
  nssm stop ShiftManager        # Stop service
  nssm restart ShiftManager     # Restart service
  nssm remove ShiftManager      # Uninstall service

Method 2: Using sc.exe (Built-in)

Create Service:
  sc create ShiftManager binPath="C:\ShiftManager\ShiftManager.exe" start=auto

Start Service:
  sc start ShiftManager

Stop Service:
  sc stop ShiftManager

Delete Service:
  sc delete ShiftManager

Method 3: Manual Service Wrapper

For advanced scenarios, create a Windows Service wrapper using:
  - .NET Worker Service template
  - Topshelf library
  - Custom Windows Service implementation

Verification:
  1. Open Services (services.msc)
  2. Find "ShiftManager" service
  3. Verify Status: Running
  4. Open http://localhost:5000
  5. Verify application accessible

Service Logs:
  - Check Event Viewer â†’ Windows Logs â†’ Application
  - Look for entries from "ShiftManager"
  - Errors will be logged here

SECTION 8: TROUBLESHOOTING
================================================================================

8.1: Application Won't Start

Problem: "SEED_ADMIN_PASSWORD must be set"
Solution:
  1. Edit appsettings.json
  2. Set SEED_ADMIN_PASSWORD to a strong password
  3. Save and restart application

Problem: "Database error" or "Migration failed"
Solution:
  1. Stop application
  2. Delete app.db, app.db-shm, app.db-wal
  3. Start application (database will be recreated)
  4. If problem persists, check file permissions

Problem: "Port 5000 is already in use"
Solution:
  Option 1: Stop other application using port 5000
    - Find process: netstat -ano | findstr ":5000"
    - Kill process: taskkill /F /PID [PID]
  Option 2: Configure different port
    - Edit appsettings.json
    - Change Kestrel:Endpoints:Http:Url to use different port
    - Example: "http://localhost:8080"

8.2: Can't Access Application

Problem: Browser can't connect
Solution:
  1. Verify application is running (check console or services)
  2. Verify correct URL: http://localhost:5000
  3. Try http://127.0.0.1:5000 instead
  4. Check Windows Firewall isn't blocking
  5. Check antivirus isn't blocking

Problem: "Access denied" or "Cannot create database"
Solution:
  1. Stop application
  2. Right-click folder â†’ Properties â†’ Security
  3. Grant your user account or IIS_IUSRS full control
  4. Apply to all files and subfolders
  5. Restart application

8.3: Authentication Issues

Problem: Can't login with admin@local
Solution:
  1. Verify SEED_ADMIN_PASSWORD is set correctly
  2. Password is case-sensitive
  3. Delete app.db and restart (creates fresh database)
  4. Check browser console for errors (F12)

Problem: "Authentication failed" errors
Solution:
  1. Clear browser cookies
  2. Try incognito/private browsing mode
  3. Check that cookies are enabled
  4. Verify system clock is correct

8.4: Database Issues

Problem: Database corruption
Solution:
  1. Stop application
  2. Backup current app.db
  3. Delete app.db, app.db-shm, app.db-wal
  4. Restore from backup if available
  5. Or start fresh (database will be recreated)

8.5: Performance Issues

Problem: Slow response times
Solution:
  1. Check disk space (database grows over time)
  2. Check RAM usage (1 GB recommended)
  3. Consider vacuuming database (SQLite maintenance)
  4. Check for antivirus interference

8.6: Upgrade Issues

See UPGRADE_GUIDE.txt for detailed upgrade troubleshooting.

8.7: Getting More Help

If you encounter issues not covered here:

  - Forward traffic to ShiftManager on localhost:5000

  - Configure Kestrel to use HTTPS
  - Update appsettings.json with certificate path
  - Bind to https://*:443

Option 3: Load Balancer
  - Use external load balancer with SSL termination
  - Forward unencrypted traffic to ShiftManager

SECTION 10: BACKUP AND MAINTENANCE
================================================================================

10.1: Database Backup

The database (app.db) contains all your data:

Manual Backup:
  1. Stop ShiftManager
  2. Copy app.db to backup location
  3. Copy app.db-shm and app.db-wal if present
  4. Name with date: app.db.backup.2025-01-15
  5. Start ShiftManager

Automated Backup Script (PowerShell):
  $date = Get-Date -Format "yyyy-MM-dd"
  Stop-Service ShiftManager
  Copy-Item "C:\ShiftManager\app.db" "C:\Backups\app.db.$date"
  Start-Service ShiftManager

Schedule with Task Scheduler:
  - Run daily at off-peak hours
  - Use Task Scheduler to automate
  - Keep last 30 days of backups
  - Test restore monthly

10.2: Database Restore

To restore from backup:
  1. Stop ShiftManager
  2. Rename current app.db to app.db.old
  3. Copy backup to app.db
  4. Delete app.db-shm and app.db-wal
  5. Start ShiftManager
  6. Verify data is correct

10.3: Database Maintenance

SQLite database maintenance:

Vacuum Database (reduce file size):
  1. Stop ShiftManager
  2. Use SQLite tool: sqlite3 app.db "VACUUM;"
  3. Start ShiftManager

Analyze Database (optimize queries):
  sqlite3 app.db "ANALYZE;"

Check Integrity:
  sqlite3 app.db "PRAGMA integrity_check;"

10.4: Disk Space Monitoring

Monitor disk space regularly:
  - Database grows over time
  - Plan for 1 MB per 1000 shifts (approximate)
  - Keep 20% free space minimum
  - Set up disk space alerts

10.5: Update Strategy

When new versions are released:
  1. Read release notes (VERSION.txt)
  2. Test in non-production environment first
  3. Backup database before upgrade
  4. Follow UPGRADE_GUIDE.txt
  5. Verify functionality after upgrade
  6. Keep backup for 1 week after upgrade
