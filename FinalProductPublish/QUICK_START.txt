STEP 1: SET ADMIN PASSWORD
================================================================================

Before you can run ShiftManager, you MUST set an admin password.

How to do it:
  1. Open "appsettings.json" in Notepad (right-click â†’ Open With â†’ Notepad)
  2. Find this line:
       "SEED_ADMIN_PASSWORD": "",
  3. Change it to:

  4. Save the file (Ctrl+S)
  5. Close Notepad

ACCESSING FROM OTHER COMPUTERS
================================================================================

By default, ShiftManager only accepts connections from localhost (this computer).

To access from other computers on your network:
  1. Stop ShiftManager (close the console window)
  2. See DEPLOYMENT_GUIDE.txt Section 6: Network Access
  3. Configure firewall rules
  4. Update appsettings.json for network binding
  5. Restart ShiftManager

================================================================================
STOPPING THE APPLICATION
================================================================================

To stop ShiftManager:
  - Close the console window (the black window with the application log)
  - Or press Ctrl+C in the console window

Your data is safe - it's stored in app.db and won't be lost.

================================================================================
TROUBLESHOOTING
================================================================================

Problem: "SEED_ADMIN_PASSWORD must be set"
Solution: You skipped Step 1. Go back and set the password in appsettings.json

Problem: "Port 5000 is already in use"
Solution:
  - Close other applications using port 5000
  - Or see DEPLOYMENT_GUIDE.txt to configure a different port

Problem: "Access denied" or "Cannot create database"
Solution:
  - Run START_HERE.bat as Administrator (right-click â†’ Run as administrator)
  - Or give your user account write permissions to this folder

Problem: Browser can't connect to http://localhost:5000
Solution:
  - Check that START_HERE.bat window is still open
  - Verify you see "Now listening on: http://localhost:5000" in the console
  - Try http://127.0.0.1:5000 instead
  - Check Windows Firewall isn't blocking the connection

Problem: Application starts but crashes after a few seconds
Solution:
  - Look for error messages in the console window
  - Check the application log file (if created)
  - See DEPLOYMENT_GUIDE.txt Section 8: Troubleshooting
