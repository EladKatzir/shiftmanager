UNDERSTANDING ALLOWEDHOSTS
═══════════════════════════════════════════════════════════════════════

The AllowedHosts setting protects against Host Header attacks.

FORMAT: Semicolon-separated list of hostnames

Examples:

1. Allow only localhost:
   "AllowedHosts": "localhost"
   ✓ http://localhost/
   ✗ https://7108dev.d8200.mil/
   ✗ http://192.168.1.100/

2. Allow specific hosts (RECOMMENDED):
   "AllowedHosts": "localhost;7108dev.d8200.mil"
   ✓ http://localhost/
   ✓ https://7108dev.d8200.mil/
   ✗ http://example.com/

3. Allow all hosts (LESS SECURE):
   "AllowedHosts": "*"
   ✓ Any hostname works
   ⚠️ Less secure - not recommended for production

4. Allow multiple specific hosts:
   "AllowedHosts": "localhost;7108dev.d8200.mil;app.example.com"
   ✓ All three hostnames work

5. Allow wildcard subdomain:
   "AllowedHosts": "localhost;*.d8200.mil"
   ✓ localhost
   ✓ 7108dev.d8200.mil
   ✓ anysubdomain.d8200.mil

═══════════════════════════════════════════════════════════════════════
SECURITY CONSIDERATIONS
═══════════════════════════════════════════════════════════════════════

Why AllowedHosts exists:
- Prevents "Host Header Injection" attacks
- Prevents "Host Header Poisoning" attacks
- Prevents attackers from spoofing the hostname

Best practices:
✅ Use specific hostnames (what we did)
✅ Include all legitimate hostnames your app uses
❌ Avoid "*" in production (use only for testing)
❌ Don't include untrusted domains

For air-gapped/internal networks:
- Security risk is lower (no internet access)
- Still recommended to use specific hosts
- Prevents internal abuse
