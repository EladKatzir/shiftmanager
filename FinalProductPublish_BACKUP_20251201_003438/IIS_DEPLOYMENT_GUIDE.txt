                  2. PRE-DEPLOYMENT PREPARATION
================================================================================

STEP 1: Verify DNS Resolution
------------------------------
On the server, open PowerShell and verify DNS:

  nslookup 7108dev.d8200.mil

Expected output:
  Name:    7108dev.d8200.mil
  Address: [Your server IP]

If DNS doesn't resolve, check with network administrator.


STEP 2: Verify SSL Certificate
-------------------------------
Open PowerShell as Administrator:

  # List all certificates in Local Machine store
  Get-ChildItem -Path Cert:\LocalMachine\My |
    Select-Object Subject, Thumbprint, NotAfter |
    Format-Table -AutoSize

Look for certificate with Subject containing:
  - 7108dev.d8200.mil OR
  - *.d8200.mil (wildcard) OR
  - CN=7108dev.d8200.mil

Note the Thumbprint (40-character hex string) - you'll need this later.

Example output:
  Subject                     Thumbprint                               NotAfter
  -------                     ----------                               --------
  CN=7108dev.d8200.mil        A1B2C3D4E5F6...                         12/31/2025


STEP 3: Check Firewall Rules
-----------------------------
Verify ports 80 and 443 are open:

  # Check if ports are listening
  netstat -ano | findstr ":80 "
  netstat -ano | findstr ":443"

  # Check Windows Firewall rules
  netsh advfirewall firewall show rule name=all | findstr "443"

If ports are not open, create firewall rules (see Troubleshooting section).


STEP 4: Prepare Deployment Folder
----------------------------------
Create deployment directory on server:

  mkdir C:\inetpub\wwwroot\ShiftManager

Transfer FinalProductPublish contents to server:
  - Copy FinalProductPublish folder to USB drive
  - Transfer to server
  - Extract to: C:\inetpub\wwwroot\ShiftManager\

                  3. IIS INSTALLATION AND CONFIGURATION
================================================================================

STEP 1: Install IIS (if not already installed)
-----------------------------------------------
Open PowerShell as Administrator:

  # Install IIS with management tools
  Install-WindowsFeature -Name Web-Server -IncludeManagementTools

  # Install required IIS features
  Install-WindowsFeature -Name Web-WebSockets
  Install-WindowsFeature -Name Web-ISAPI-Ext
  Install-WindowsFeature -Name Web-ISAPI-Filter

  # Verify installation
  Get-WindowsFeature -Name Web-Server


STEP 2: Install .NET Core Hosting Bundle
-----------------------------------------
CRITICAL: Even though FinalProductPublish is self-contained, IIS requires
the ASP.NET Core Module for proper hosting.

Download and install .NET 8.0 Hosting Bundle:

Option A - If server has internet:
  1. Download from: https://dotnet.microsoft.com/download/dotnet/8.0
  2. Look for: "Hosting Bundle" under .NET Runtime
  3. Run installer: dotnet-hosting-8.0.x-win.exe
  4. Restart IIS: iisreset

Option B - Air-gapped server (recommended for military environment):
  1. Download Hosting Bundle on internet-connected machine
  2. Copy installer to USB drive
  3. Transfer to server
  4. Run: dotnet-hosting-8.0.x-win.exe
  5. Restart IIS: iisreset

VERIFY INSTALLATION:
  # Check ASP.NET Core Module is installed
  Get-WebGlobalModule | Where-Object {$_.Name -like "*AspNetCore*"}

Expected output:
  Name                       Image
  ----                       -----
  AspNetCoreModuleV2         C:\Program Files\IIS\...


STEP 3: Restart IIS
-------------------
After installing Hosting Bundle:

  iisreset

Wait 30 seconds for IIS to restart completely.

                  5. APPLICATION POOL CONFIGURATION
================================================================================

STEP 1: Create Application Pool
--------------------------------
Open IIS Manager (inetmgr) or use PowerShell:

PowerShell method (recommended):
  Import-Module WebAdministration

  # Create new application pool
  New-WebAppPool -Name "ShiftManagerAppPool"

  # Configure application pool settings
  Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool -Name managedRuntimeVersion -Value ""
  Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool -Name enable32BitAppOnWin64 -Value $false
  Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool -Name processModel.identityType -Value 4

  # Set recycling schedule (optional - restart at 3 AM daily)
  Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool -Name recycling.periodicRestart.time -Value "00:00:00"
  Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool -Name recycling.periodicRestart.schedule -Value @{value="03:00:00"}


IIS Manager GUI method:
  1. Open IIS Manager (Start → inetmgr)
  2. Expand server node in left panel
  3. Click "Application Pools"
  4. Right-click in middle panel → "Add Application Pool"
  5. Configure:
     - Name: ShiftManagerAppPool
     - .NET CLR Version: No Managed Code
     - Managed pipeline mode: Integrated
  6. Click OK
  7. Right-click ShiftManagerAppPool → Advanced Settings
  8. Set:
     - Enable 32-Bit Applications: False
     - Identity: ApplicationPoolIdentity
     - Start Mode: AlwaysRunning (optional, for better performance)


STEP 2: Configure Application Pool Advanced Settings
-----------------------------------------------------
In IIS Manager, right-click ShiftManagerAppPool → Advanced Settings:

PROCESS MODEL:
  - Identity: ApplicationPoolIdentity (default)
  - Idle Time-out: 20 (minutes) OR 0 (never timeout)
  - Maximum Worker Processes: 1 (increase for high load)

RECYCLING:
  - Regular Time Interval: 1740 (29 hours) OR 0 (disable)
  - Specific Times: 03:00 (3 AM daily restart)

RAPID-FAIL PROTECTION:
  - Enabled: True
  - Failure Interval: 5 (minutes)
  - Maximum Failures: 5

CPU:
  - Limit: 0 (no limit)
  - Limit Action: NoAction

STEP 2: Add HTTPS Binding
--------------------------
PowerShell method:

  # First, get your certificate thumbprint
  $cert = Get-ChildItem -Path Cert:\LocalMachine\My |
    Where-Object {$_.Subject -like "*7108dev.d8200.mil*"}

  # Display certificate details
  $cert | Select-Object Subject, Thumbprint, NotAfter

  # Add HTTPS binding
  New-WebBinding -Name "ShiftManager" `
    -Protocol https `
    -Port 443 `
    -HostHeader "7108dev.d8200.mil" `
    -SslFlags 1

  # Bind certificate to HTTPS binding
  $binding = Get-WebBinding -Name "ShiftManager" -Protocol https
  $binding.AddSslCertificate($cert.Thumbprint, "My")


IIS Manager GUI method:
  1. In IIS Manager, select "ShiftManager" website
  2. Right panel → "Bindings"
  3. Click "Add"
  4. Configure HTTPS binding:
     - Type: https
     - IP address: All Unassigned
     - Port: 443
     - Host name: 7108dev.d8200.mil
     - SSL certificate: [Select your certificate for 7108dev.d8200.mil]
  5. Click OK


STEP 3: Configure HTTP to HTTPS Redirect (Recommended)
-------------------------------------------------------
Force all HTTP traffic to redirect to HTTPS.

Install URL Rewrite module (if not installed):
  1. Download from: https://www.iis.net/downloads/microsoft/url-rewrite
  2. Or use Web Platform Installer
  3. Install and restart IIS

Create web.config in C:\inetpub\wwwroot\ShiftManager:

  <?xml version="1.0" encoding="utf-8"?>
  <configuration>
    <location path="." inheritInInChildApplications="false">
      <system.webServer>
        <handlers>
          <add name="aspNetCore" path="*" verb="*" modules="AspNetCoreModuleV2" resourceType="Unspecified" />
        </handlers>
        <aspNetCore processPath=".\ShiftManager.exe"
                    stdoutLogEnabled="true"
                    stdoutLogFile=".\logs\stdout"
                    hostingModel="inprocess">
          <environmentVariables>
            <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
          </environmentVariables>
        </aspNetCore>
        <rewrite>
          <rules>
            <rule name="HTTP to HTTPS redirect" stopProcessing="true">
              <match url="(.*)" />
              <conditions>
                <add input="{HTTPS}" pattern="off" ignoreCase="true" />
              </conditions>
              <action type="Redirect" url="https://{HTTP_HOST}/{R:1}" redirectType="Permanent" />
            </rule>
          </rules>
        </rewrite>
      </system.webServer>
    </location>
  </configuration>

  IP:port                 : 0.0.0.0:443

  Application ID          : {[GUID]}
  Certificate Store Name  : MY
  Verify Client Certificate Revocation : Enabled


MANUAL CERTIFICATE BINDING (if automatic binding failed):
----------------------------------------------------------
  # Get certificate thumbprint
  $cert = Get-ChildItem Cert:\LocalMachine\My |
    Where-Object {$_.Subject -like "*7108dev.d8200.mil*"}

  $thumbprint = $cert.Thumbprint

  # Bind certificate to port 443
  netsh http add sslcert ipport=0.0.0.0:443 `
    certhash=$thumbprint `
    appid='{[Random-GUID]}' `
    certstorename=MY

Replace [Random-GUID] with a new GUID (PowerShell: New-Guid)

================================================================================
                  11. TROUBLESHOOTING
================================================================================

ISSUE 1: Website won't start
-----------------------------
SYMPTOM: Website state shows "Stopped" or errors when starting

SOLUTIONS:
  1. Check Application Pool:
     Get-WebAppPool -Name "ShiftManagerAppPool"

     If stopped:
     Start-WebAppPool -Name "ShiftManagerAppPool"

  2. Check Event Viewer:
     eventvwr.msc → Windows Logs → Application
     Look for errors from "IIS AspNetCore Module V2"

  3. Check stdout logs:
     type C:\inetpub\wwwroot\ShiftManager\logs\stdout_*.log

  4. Verify .NET Hosting Bundle installed:
     Get-WebGlobalModule | Where-Object {$_.Name -like "*AspNetCore*"}


ISSUE 2: 502.5 Process Failure
-------------------------------
SYMPTOM: Browser shows "HTTP Error 502.5 - Process Failure"

SOLUTIONS:
  1. DLLs are blocked:
     cd C:\inetpub\wwwroot\ShiftManager
     Get-ChildItem -Recurse -Filter *.dll | Unblock-File

  2. Check file permissions:
     icacls "C:\inetpub\wwwroot\ShiftManager" /grant IIS_IUSRS:(OI)(CI)M

  3. Verify ShiftManager.exe exists and is not corrupted:
     dir ShiftManager.exe
     Should be ~148 KB

  4. Check stdout logs for detailed error


ISSUE 3: 500 Internal Server Error
-----------------------------------
SYMPTOM: Generic 500 error in browser

SOLUTIONS:
  1. Enable detailed errors temporarily:
     Edit web.config, add to <aspNetCore> section:
     stdoutLogEnabled="true"

  2. Check application logs:
     type C:\inetpub\wwwroot\ShiftManager\logs\stdout_*.log

  3. Check database permissions:
     icacls "C:\inetpub\wwwroot\ShiftManager\app.db"
     Should have IIS_IUSRS with Modify permissions

  4. Check appsettings.json:
     - Verify valid JSON (no syntax errors)
     - Check connection string is correct
     - Verify AllowedHosts matches your domain


ISSUE 4: Certificate Warning / Not Trusted
-------------------------------------------
SYMPTOM: Browser shows "Your connection is not private" or certificate error

SOLUTIONS:
  1. Verify certificate is for correct domain:
     $cert = Get-ChildItem Cert:\LocalMachine\My |
       Where-Object {$_.Subject -like "*7108dev.d8200.mil*"}
     $cert | Select-Object Subject, Thumbprint, NotAfter

  2. Check certificate not expired:
     If NotAfter is in the past, certificate is expired - request new one

  3. Verify certificate is in correct store:
     Must be in: Cert:\LocalMachine\My (Personal)

  4. Check certificate chain:
     Ensure intermediate and root CA certificates are installed

  5. Verify HTTPS binding:
     Get-WebBinding -Name "ShiftManager" -Protocol https


ISSUE 5: Port 443 already in use
---------------------------------
SYMPTOM: Error binding to port 443

SOLUTIONS:
  1. Check what's using port 443:
     netstat -ano | findstr ":443"

  2. If Default Web Site is using it:
     Stop-Website -Name "Default Web Site"

  3. Or change Default Web Site to different port/host header


ISSUE 6: Cannot write to database
----------------------------------
SYMPTOM: Errors about database being locked or read-only

SOLUTIONS:
  1. Check folder permissions:
     icacls "C:\inetpub\wwwroot\ShiftManager"

     Grant write permissions:
     icacls "C:\inetpub\wwwroot\ShiftManager" /grant IIS_IUSRS:(OI)(CI)M

  2. Check if app.db is read-only:
     attrib C:\inetpub\wwwroot\ShiftManager\app.db

     Remove read-only:
     attrib -R C:\inetpub\wwwroot\ShiftManager\app.db

  3. Restart application pool:
     Restart-WebAppPool -Name "ShiftManagerAppPool"


ISSUE 7: File uploads not working
----------------------------------
SYMPTOM: Avatar uploads or feedback file uploads fail

SOLUTIONS:
  1. Create feedback folder if missing:
     mkdir C:\inetpub\wwwroot\ShiftManager\wwwroot\feedback

  2. Set permissions:
     icacls "C:\inetpub\wwwroot\ShiftManager\wwwroot\feedback" /grant IIS_IUSRS:(OI)(CI)W

  3. Check IIS upload limits (default 30 MB):
     Edit web.config, add to <system.webServer>:
     <security>
       <requestFiltering>
         <requestLimits maxAllowedContentLength="104857600" />
       </requestFiltering>
     </security>

     Note: 104857600 = 100 MB in bytes


ISSUE 8: Application runs slow or times out
--------------------------------------------
SYMPTOM: Pages load slowly or timeout errors

SOLUTIONS:
  1. Check application pool is not stopping:
     Set Idle Timeout to 0 (never timeout):
     Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool `
       -Name processModel.idleTimeout -Value "00:00:00"

  2. Enable AlwaysRunning:
     Set-ItemProperty IIS:\AppPools\ShiftManagerAppPool `
       -Name startMode -Value AlwaysRunning

  3. Check server resources (CPU, RAM, Disk):
     Task Manager → Performance tab

  4. Check for database locking issues:
     SQLite may lock if multiple processes access it
     Ensure only one app pool instance


ISSUE 9: Firewall blocking access
----------------------------------
SYMPTOM: Can't access from other machines on network

SOLUTIONS:
  1. Check Windows Firewall:
     Get-NetFirewallRule | Where-Object {$_.DisplayName -like "*443*"}

  2. Create firewall rule for HTTPS:
     New-NetFirewallRule -DisplayName "HTTPS In" `
       -Direction Inbound `
       -LocalPort 443 `
       -Protocol TCP `
       -Action Allow

  3. Create firewall rule for HTTP (if needed):
     New-NetFirewallRule -DisplayName "HTTP In" `
       -Direction Inbound `
       -LocalPort 80 `
       -Protocol TCP `
       -Action Allow

  4. Check network firewall/router:
     Verify ports 80 and 443 are not blocked by network firewall


ISSUE 10: "Could not load file or assembly" error
--------------------------------------------------
SYMPTOM: Error about unable to load DLL or assembly

SOLUTIONS:
  1. Unblock ALL DLLs:
     cd C:\inetpub\wwwroot\ShiftManager
     Get-ChildItem -Recurse -Filter *.dll | Unblock-File

  2. Install Visual C++ Redistributables (for e_sqlite3.dll):
     Download and install:
     - VC++ 2015-2022 Redistributable (x64)

  3. Verify all 336 DLLs are present:
     (Get-ChildItem -Recurse -Filter *.dll).Count
     Expected: 336

RECOMMENDED PRODUCTION SETTINGS:
---------------------------------

1. Update appsettings.json:

  {
    "ConnectionStrings": {
      "Default": "Data Source=app.db"
    },
    "Logging": {
      "LogLevel": {
        "Default": "Warning",
        "Microsoft.AspNetCore": "Warning",
        "Microsoft.Hosting.Lifetime": "Information"
      }
    },
    "AllowedHosts": "7108dev.d8200.mil",
    "Features": {
      "EnforceCompanyScope": true,
      "EnableDirectorRole": true,
      "AllowPublicSignup": false,  // Set to false for production
      "EnableApiKeyManagement": true
    },
    "Email": {
      "Enabled": false  // Enable if you have email server
    },
    "SEED_ADMIN_PASSWORD": ""  // Empty after first run (password already created)
  }


2. Security Headers (add to web.config):

  <system.webServer>
    <httpProtocol>
      <customHeaders>
        <remove name="X-Powered-By" />
        <add name="X-Frame-Options" value="SAMEORIGIN" />
        <add name="X-Content-Type-Options" value="nosniff" />
        <add name="X-XSS-Protection" value="1; mode=block" />
        <add name="Referrer-Policy" value="strict-origin-when-cross-origin" />
      </customHeaders>
    </httpProtocol>
  </system.webServer>


3. Application Pool Settings:

  - Recycling: 03:00 AM daily
  - Idle Timeout: 0 (never timeout)
  - Start Mode: AlwaysRunning
  - Maximum Worker Processes: 1 (or more for high load)


4. IIS Security:

  - Disable directory browsing (done above)
  - Enable Request Filtering
  - Set maximum URL length: 4096 bytes
  - Set maximum query string: 2048 bytes


5. Database Backup:

Create scheduled task to backup app.db daily:

  # Backup script (save as C:\Scripts\BackupShiftManager.ps1):
  $date = Get-Date -Format "yyyyMMdd_HHmmss"
  $source = "C:\inetpub\wwwroot\ShiftManager\app.db"
  $dest = "C:\Backups\ShiftManager\app_$date.db"

  if (Test-Path $source) {
      Copy-Item $source $dest

      # Keep only last 30 days
      Get-ChildItem "C:\Backups\ShiftManager" |
        Where-Object {$_.LastWriteTime -lt (Get-Date).AddDays(-30)} |
        Remove-Item
  }

Create scheduled task:
  schtasks /create /tn "Backup ShiftManager" `
    /tr "powershell.exe -File C:\Scripts\BackupShiftManager.ps1" `
    /sc daily /st 02:00

UPDATING THE APPLICATION:
--------------------------
