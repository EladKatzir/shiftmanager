COMMON ERRORS AND SOLUTIONS
═══════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #1: "500.0 - ANCM In-Process Handler Load Failure"           │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: AspNetCoreModuleV2 (ANCM) is not installed or wrong version

SOLUTION:
1. Download .NET 8.0 Hosting Bundle:
   https://dotnet.microsoft.com/download/dotnet/8.0

2. Look for: "Hosting Bundle" for Windows Server
   File: dotnet-hosting-8.0.x-win.exe

3. Install it on the IIS server

4. Restart IIS:
   Open Command Prompt as Administrator:
   > net stop was /y
   > net start w3svc

5. Restart your Application Pool in IIS Manager

6. Test again


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #2: "Could not load file or assembly 'SixLabors.ImageSharp'" │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: DLL files are blocked by Windows

SOLUTION A (Automatic):
1. In FinalProductPublish folder, run: UNBLOCK_FILES.bat
2. Restart IIS Application Pool
3. Test again

SOLUTION B (Manual):
1. Open PowerShell as Administrator
2. Navigate to FinalProductPublish folder
3. Run:
   Get-ChildItem -Path . -Recurse | Unblock-File
4. Restart IIS Application Pool
5. Test again


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #3: "Access Denied" or "Permission Denied"                   │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: IIS doesn't have permission to access files or create database

SOLUTION:
1. Open Command Prompt as Administrator
2. Navigate to FinalProductPublish folder
3. Run these commands:

   icacls . /grant "IIS_IUSRS:(OI)(CI)RX" /T
   icacls . /grant "IIS_IUSRS:(OI)(CI)M"
   icacls . /grant "IUSR:(OI)(CI)RX" /T
   icacls . /grant "IUSR:(OI)(CI)M"

4. If app.db exists:
   icacls app.db /grant "IIS_IUSRS:M"

5. Restart Application Pool
6. Test again


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #4: "Failed to start application" or "Application startup    │
│           exception"                                                 │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: Application code error (database, configuration, etc.)

SOLUTION:
1. Check the stdout logs:
   - Open folder: FinalProductPublish\logs\
   - Open the most recent stdout_*.log file
   - Look for error messages near the end

2. Common issues in logs:

   a) "SQLite Error: unable to open database file"
      → Fix: Run IIS_QUICK_FIX.bat to set permissions

   b) "Could not load file or assembly"
      → Fix: Run UNBLOCK_FILES.bat

   c) "The configuration file 'appsettings.json' was not found"
      → Fix: Verify appsettings.json exists in root folder

   d) Any other error → Copy the error message and see below


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #5: "HTTP Error 500.31 - Failed to load ASP.NET Core runtime"│
└─────────────────────────────────────────────────────────────────────┘

CAUSE: .NET 8.0 Runtime not installed or wrong architecture (x86 vs x64)

SOLUTION:
1. This is a self-contained deployment, so this should NOT happen
2. Verify web.config has:
   processPath=".\ShiftManager.exe" (NOT dotnet.exe)

3. If web.config looks wrong, restore it:
   copy /Y web.config.enhanced web.config

4. Restart Application Pool


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #6: "HTTP Error 500.30 - ASP.NET Core app failed to start"  │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: Multiple possible issues

SOLUTION - Step by step:
1. Check logs\stdout*.log for the actual error
2. Common causes:

   a) Database locked:
      - Stop all instances of ShiftManager.exe:
        taskkill /F /IM ShiftManager.exe
      - Delete app.db (it will recreate)
      - Restart Application Pool

   b) Port conflict:
      - Not applicable for IIS (IIS doesn't use port 5000)
      - This error means something else

   c) Configuration error:
      - Check appsettings.json is valid JSON
      - Verify SEED_ADMIN_PASSWORD is set
      - Check no trailing commas in JSON


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #7: Page shows but no styling (CSS/JS not loading)          │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: Static files not being served

SOLUTION:
1. Verify wwwroot folder exists with css/ and js/ subfolders
2. Set permissions:
   icacls wwwroot /grant "IIS_IUSRS:(OI)(CI)RX" /T
3. Check web.config has static file handlers enabled
4. In IIS Manager:
   - Select your site
   - Handler Mappings → Check StaticFile is enabled
5. Restart Application Pool


┌─────────────────────────────────────────────────────────────────────┐
│ ERROR #8: "The page cannot be displayed" or connection timeout     │
└─────────────────────────────────────────────────────────────────────┘

CAUSE: IIS site not running or DNS/firewall issue

SOLUTION:
1. Open IIS Manager
2. Check if site is Started (right panel shows "Stop", not "Start")
3. If stopped, click Start
4. Check Application Pool:
   - Application Pools → Your pool → Should show "Started"
   - If stopped, right-click → Start
5. Test locally first:
   - On the server, open browser
   - Go to: http://localhost/
   - Should work
6. Then test from another machine

═══════════════════════════════════════════════════════════════════════
MANUAL DIAGNOSTIC CHECKS
═══════════════════════════════════════════════════════════════════════

Check #1: Is AspNetCoreModuleV2 Installed?
───────────────────────────────────────────
Run in Command Prompt:
  reg query "HKLM\SOFTWARE\Microsoft\IIS Extensions\IIS AspNetCore Module V2"

If error → Not installed → Install Hosting Bundle

Check #2: Are DLLs Blocked?
────────────────────────────
Run in PowerShell:
  Get-ChildItem -Recurse | ForEach-Object {
    if (Test-Path "$($_.FullName):Zone.Identifier") {
      Write-Host "BLOCKED: $($_.Name)"
    }
  }

If any BLOCKED output → Run UNBLOCK_FILES.bat

Check #3: Can App Start Standalone?
────────────────────────────────────
1. Open Command Prompt in FinalProductPublish folder
2. Run: ShiftManager.exe
3. Wait 10 seconds
4. Should see: "Now listening on: http://localhost:5000"
5. If yes → Problem is IIS configuration
6. If no → Problem is application/dependencies
7. Press Ctrl+C to stop

Check #4: Application Pool Identity
────────────────────────────────────
1. Open IIS Manager
2. Application Pools → Your pool → Advanced Settings
3. Process Model → Identity
4. Should be: ApplicationPoolIdentity (recommended)
5. Or: NetworkService (also works)
6. Or: Specific user account (needs proper permissions)

Check #5: Application Pool .NET Version
────────────────────────────────────────
1. Open IIS Manager
2. Application Pools → Your pool → Basic Settings
3. .NET CLR Version: "No Managed Code"
   (This is CORRECT for ASP.NET Core!)
4. Managed Pipeline Mode: Integrated
