================================================================================
                    UPGRADE GUIDE - ShiftManager v1.0.0
                Upgrading from Previous Versions to v1.0.0
================================================================================

This guide covers upgrading from an older version of ShiftManager to the new
v1.0.0 deployment package.

================================================================================
SCENARIO 1: UPGRADING WHILE OLD VERSION IS RUNNING
================================================================================

If the old ShiftManager is currently running, follow these steps:

OPTION A: Using START_HERE.bat (Recommended - Automated)
----------------------------------------------------------
1. Run the new START_HERE.bat
2. You'll see: "[WARNING] ShiftManager is already running!"
3. Press 'S' to automatically STOP the old version
4. The script will:
   - Stop the running ShiftManager.exe process
   - Wait for file locks to release (4 seconds)
   - Continue with startup checks
5. Follow remaining prompts

OPTION B: Manual Process
------------------------
1. Stop the old ShiftManager:
   - Method 1: Press Ctrl+C in the console window where it's running
   - Method 2: Close the console window
   - Method 3: Task Manager → Find ShiftManager.exe → End Task

2. Wait 5 seconds for file locks to release

3. Run the new START_HERE.bat

================================================================================
SCENARIO 2: REPLACING OLD PROJECTPUBLISH FOLDER
================================================================================

If you want to completely replace the old deployment:

STEP 1: Stop the Running Application
-------------------------------------
- Stop ShiftManager.exe (see methods above)
- Verify it's stopped: Task Manager → check ShiftManager.exe is gone

STEP 2: Backup Your Database (CRITICAL!)
-----------------------------------------
If you have existing data you want to keep:

1. Navigate to old ProjectPublish folder
2. Copy these files to a safe location:
   - app.db (your database)
   - app.db-shm (if exists)
   - app.db-wal (if exists)
   - appsettings.json (your configuration)

STEP 3: Replace the Folder
---------------------------
1. Delete or rename old ProjectPublish folder
   Example: Rename to "ProjectPublish_OLD_20251112"

2. Copy new ProjectPublish folder to the same location

3. If you backed up database files:
   - Copy app.db (and related files) to new ProjectPublish folder
   - This preserves your existing data

4. If you backed up appsettings.json:
   - Copy your SEED_ADMIN_PASSWORD value to new appsettings.json
   - Review new settings (AllowedHosts, API endpoints, etc.)

STEP 4: Start New Version
--------------------------
1. Run START_HERE.bat from new folder
2. Follow on-screen instructions

================================================================================
SCENARIO 3: SIDE-BY-SIDE INSTALLATION
================================================================================

To run both versions for testing:

1. Keep old ProjectPublish folder as-is
2. Copy new ProjectPublish to different location
   Example: C:\ShiftManager_NEW\

3. Update port in NEW version:
   - Edit new ProjectPublish\appsettings.json
   - Add after line 10:
     "Kestrel": {
       "Endpoints": {
         "Http": {
           "Url": "http://localhost:5001"
         }
       }
     },

4. Now you can run:
   - Old version: http://localhost:5000
   - New version: http://localhost:5001

5. Stop old version when ready to switch permanently

================================================================================
SCENARIO 4: CLEAN INSTALLATION (NO DATA TO PRESERVE)
================================================================================

If you don't need to keep the old database:

1. Stop old ShiftManager.exe
2. Delete entire old ProjectPublish folder
3. Copy new ProjectPublish folder
4. Edit appsettings.json (set SEED_ADMIN_PASSWORD)
5. Run START_HERE.bat

IMPORTANT: This creates a fresh database. All old data will be lost!

================================================================================
DATABASE COMPATIBILITY
================================================================================

Database Structure Changes from Old to New:
-------------------------------------------
The v1.0.0 database has 22 migrations and includes new features:

NEW TABLES:
  - ApiKeys (API key management)
  - ApiKeyScopes (API permissions)
  - AuditLogs (enhanced audit logging)
  - Chores (chore assignments)
  - DirectorCompanies (director access)
  - OnDuty (on-duty assignments)
  - OnDutyTypeConfig (custom on-duty types)
  - TeamCalendarEvents (team calendars)
  - TeamCalendarMembers (calendar membership)
  - UserJoinRequests (signup requests)

NEW COLUMNS:
  - Users table: Profile fields, lockout fields, security fields
  - ShiftTypes: CustomName field
  - TimeOffRequests: ReviewedBy field
  - And many more...

Migration Process:
------------------
When you start v1.0.0 with an old database:

1. Entity Framework detects missing migrations
2. Automatically applies all new migrations (if possible)
3. Existing data is preserved
4. New tables and columns are added

RISK: If migrations fail, you may need to restore from backup!

Recommendation: ALWAYS backup app.db before upgrading!

================================================================================
PORT CONFLICT RESOLUTION
================================================================================

If START_HERE.bat warns about port 5000 in use:

OPTION 1: Stop the Other Application
-------------------------------------
1. Press Ctrl+C to cancel START_HERE.bat
2. Find what's using port 5000:
   netstat -ano | findstr ":5000"
3. Stop that application
4. Run START_HERE.bat again

OPTION 2: Change ShiftManager Port
-----------------------------------
1. Edit appsettings.json
2. Add after line 10:
   "Kestrel": {
     "Endpoints": {
       "Http": {
         "Url": "http://localhost:5001"
       }
     }
   },
3. Save file
4. Run START_HERE.bat
5. Access at: http://localhost:5001

================================================================================
FILE LOCK ISSUES
================================================================================

If you get "file in use" errors:

Symptoms:
  - Cannot copy new files over old ones
  - "Access denied" or "File in use" errors
  - app.db is locked

Solution:
1. Stop ShiftManager.exe completely
2. Wait 10 seconds (file handles may take time to close)
3. Check Task Manager - ensure ShiftManager.exe is gone
4. If still locked, restart Windows
5. Try again

================================================================================
CONFIGURATION MIGRATION
================================================================================

Key Configuration Changes in v1.0.0:
------------------------------------

OLD appsettings.json might not have:
  - SEED_ADMIN_PASSWORD (NEW - required)
  - SEED_DIRECTOR_PASSWORD (NEW - optional)
  - AllowedHosts might be "localhost" instead of "*"
  - EnforceCompanyScope might be missing
  - All API endpoint flags (new)

To Migrate Configuration:
--------------------------
1. Open OLD appsettings.json
2. Copy any custom values you set:
   - ConnectionStrings (if changed)
   - Custom ports (if configured)
   - Any other customizations

3. Open NEW appsettings.json
4. Paste your custom values
5. Add SEED_ADMIN_PASSWORD (required)
6. Review new settings (especially API flags)

================================================================================
VERIFICATION AFTER UPGRADE
================================================================================

After upgrading, verify:

1. Application Starts
   ✓ No errors in console
   ✓ "Now listening on: http://localhost:5000"

2. Login Works
   ✓ Can access http://localhost:5000
   ✓ Login page appears
   ✓ Can login with credentials

3. Data Preserved (if upgraded database)
   ✓ Existing users are present
   ✓ Existing shifts are visible
   ✓ Historical data intact

4. New Features Available
   ✓ OFFLINE shift type appears in shift types list
   ✓ On-Duty section shows Hakam/Lead options
   ✓ Team Calendars page accessible
   ✓ Language switcher (English/Hebrew) works
   ✓ API endpoints respond (if enabled)

5. Database Integrity
   ✓ No migration errors in console
   ✓ app.db file exists and is larger than before
   ✓ All pages load without errors

================================================================================
ROLLBACK PROCEDURE (IF UPGRADE FAILS)
================================================================================

If the upgrade causes problems:

1. Stop new ShiftManager.exe
2. Restore backup files:
   - Copy backed up app.db back to folder
   - Copy backed up appsettings.json back to folder
3. If you replaced the entire folder:
   - Delete new ProjectPublish folder
   - Rename ProjectPublish_OLD back to ProjectPublish
4. Start old version
5. Verify everything works

IMPORTANT: This is why backing up app.db is critical!

================================================================================
COMMON UPGRADE ISSUES
================================================================================

ISSUE 1: "Port 5000 already in use"
------------------------------------
Solution: See "PORT CONFLICT RESOLUTION" section above

ISSUE 2: "SEED_ADMIN_PASSWORD must be set"
-------------------------------------------
Solution: Edit appsettings.json, add:
  "SEED_ADMIN_PASSWORD": "YourPassword123!",

ISSUE 3: Database migration errors
-----------------------------------
Solution:
  - Check console for specific error
  - Restore from backup
  - Contact support with error details

ISSUE 4: "Access denied" when copying files
--------------------------------------------
Solution: See "FILE LOCK ISSUES" section above

ISSUE 5: Old data disappeared
------------------------------
Cause: Probably overwrote app.db with fresh database
Solution:
  - Restore app.db from backup
  - Don't run application without your backed up database

ISSUE 6: Cannot login with old password
----------------------------------------
Cause: Fresh database created with new SEED_ADMIN_PASSWORD
Solution:
  - If you want old database: Restore app.db from backup
  - If you want fresh start: Use the password from appsettings.json

================================================================================
BEST PRACTICES FOR UPGRADES
================================================================================

1. ALWAYS backup app.db before upgrading
2. Stop old version completely before starting new version
3. Test new version in side-by-side setup first (different port)
4. Keep old ProjectPublish folder until you're sure new version works
5. Document your custom configuration settings
6. Read VERSION.txt to understand what changed
7. Verify all critical functionality after upgrade
