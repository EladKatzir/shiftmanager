================================================================================
        SHIFTMANAGER - AIR-GAPPED DEPLOYMENT GUIDE
        Windows Server 2022
================================================================================

OVERVIEW
--------
This folder contains a fully self-contained deployment of ShiftManager.
All dependencies are included - no internet connection required.

PREREQUISITES (Already Installed on Server)
--------------------------------------------
✓ Windows Server 2022
✓ .NET 8.0 Hosting Bundle
✓ .NET 8.0 SDK
✓ .NET 8.0 Runtime

IMPORTANT NOTES BEFORE DEPLOYMENT
----------------------------------
1. This is a SELF-CONTAINED deployment - all .NET runtime files are included
2. The SQLite database (app.db) will be created automatically on first run
3. Default admin credentials are configured via environment variables (see below)
4. The application uses port 5000 (HTTP) by default - you can change this

================================================================================
DEPLOYMENT STEPS
================================================================================

STEP 1: TRANSFER FILES
----------------------
1. Copy the entire "ProjectPublish" folder to your Windows Server 2022
2. Example destination: C:\ShiftManager\
3. After copying, your folder should contain:
   - ShiftManager.exe (main application)
   - All .dll files (dependencies)
   - wwwroot folder (static web files)
   - appsettings.json (configuration)
   - Migrations folder (database migrations)
   - Resources folder (localization files - English & Hebrew)

STEP 2: CONFIGURE ADMIN PASSWORD (CRITICAL - CHOOSE ONE METHOD)
----------------------------------------------------------------
The application REQUIRES an admin password to be configured before first run.
On first run, the application will:
  - Create the SQLite database (app.db)
  - Run all database migrations
  - Seed initial data (company, shift types, admin user)

⚠️ IMPORTANT: You MUST use ONE of the methods below before running the app!

================================================================================
METHOD 1: Edit appsettings.json (EASIEST - RECOMMENDED FOR AIR-GAPPED)
================================================================================
This is the SIMPLEST method and works perfectly on air-gapped servers.

1. Open appsettings.json in a text editor (Notepad, Notepad++, etc.)
2. Find these lines near the bottom:
   "SEED_ADMIN_PASSWORD": "",
   "SEED_DIRECTOR_PASSWORD": ""

3. Change to:
   "SEED_ADMIN_PASSWORD": "YourSecurePassword123!",
   "SEED_DIRECTOR_PASSWORD": ""

4. Save the file

COMPLETE EXAMPLE appsettings.json:
{
  "ConnectionStrings": {
    "Default": "Data Source=app.db"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "Features": {
    "EnforceCompanyScope": false,
    "EnableDirectorRole": true
  },
  "SEED_ADMIN_PASSWORD": "YourSecurePassword123!",
  "SEED_DIRECTOR_PASSWORD": ""
}

⚠️ SECURITY NOTE: Make sure to protect appsettings.json with NTFS permissions
   so only administrators can read it (it contains your admin password).

================================================================================
METHOD 2: Use Environment Variables (RECOMMENDED FOR PRODUCTION)
================================================================================
This is more secure as passwords aren't stored in config files.

OPTION A - PowerShell (Current Session Only):
  1. Open PowerShell as Administrator
  2. Run these commands:
     $env:SEED_ADMIN_PASSWORD = "YourSecurePassword123!"
     $env:ASPNETCORE_ENVIRONMENT = "Production"
  3. In the SAME PowerShell window, run the app:
     cd C:\ShiftManager\ProjectPublish
     .\ShiftManager.exe

OPTION B - Command Prompt (Current Session Only):
  1. Open Command Prompt as Administrator
  2. Run these commands:
     set SEED_ADMIN_PASSWORD=YourSecurePassword123!
     set ASPNETCORE_ENVIRONMENT=Production
  3. In the SAME Command Prompt window, run the app:
     cd C:\ShiftManager\ProjectPublish
     ShiftManager.exe

OPTION C - System Environment Variables (PERSISTENT - Best for Services):
  1. Press Windows Key + Pause/Break (or Right-click "This PC" → Properties)
  2. Click "Advanced system settings"
  3. Click "Environment Variables" button
  4. Under "System variables" section, click "New"
  5. Add first variable:
     - Variable name: SEED_ADMIN_PASSWORD
     - Variable value: YourSecurePassword123!
     - Click OK
  6. Add second variable (optional but recommended):
     - Variable name: ASPNETCORE_ENVIRONMENT
     - Variable value: Production
     - Click OK
  7. Click OK to close all dialogs
  8. RESTART any open command prompts or services

  NOTE: For Windows Services, you may need to restart the service or the
        entire server for environment variables to take effect.

OPTION D - Set Environment Variable in Windows Service (Using NSSM):
  If running as a Windows Service with NSSM:
  1. Run: nssm edit ShiftManager
  2. Go to "Environment" tab
  3. Add:
     SEED_ADMIN_PASSWORD=YourSecurePassword123!
     ASPNETCORE_ENVIRONMENT=Production
  4. Click "Edit service"
  5. Restart the service: nssm restart ShiftManager

OPTION E - Set Environment Variable for IIS Application Pool:
  If running under IIS:
  1. Open IIS Manager
  2. Select Application Pools
  3. Right-click your app pool → Advanced Settings
  4. Find "Environment Variables" (or configure in web.config)
  5. Or edit web.config to add:
     <aspNetCore processPath=".\ShiftManager.exe" ...>
       <environmentVariables>
         <environmentVariable name="SEED_ADMIN_PASSWORD" value="YourSecurePassword123!" />
         <environmentVariable name="ASPNETCORE_ENVIRONMENT" value="Production" />
       </environmentVariables>
     </aspNetCore>

================================================================================
IMPORTANT PASSWORD REQUIREMENTS:
================================================================================
  ✓ Choose a STRONG password (minimum 8 characters recommended)
  ✓ Use a mix of uppercase, lowercase, numbers, and symbols
  ✓ This creates the initial admin user: admin@local
  ✓ You can change the password after first login through the UI

WHAT HAPPENS IF YOU DON'T SET THE PASSWORD:
  ❌ The app will CRASH on startup with this error:
     "SEED_ADMIN_PASSWORD environment variable must be set in production"
  ✓ SOLUTION: Use METHOD 1 (edit appsettings.json) - it's the easiest!

OPTIONAL ENVIRONMENT VARIABLES:
  - SEED_DIRECTOR_PASSWORD: Password for test director user (only needed if EnableDirectorRole is true)
  - ConnectionStrings__Default: Custom database path (default: app.db in app folder)
    Example: "Data Source=C:\ShiftManager\production.db"

STEP 3: VERIFY FOLDER PERMISSIONS
----------------------------------
The application needs write permissions to create the database file:
1. Right-click the folder containing ShiftManager.exe
2. Properties → Security tab
3. Ensure the user running the app has "Modify" permissions
4. If using IIS, ensure the IIS Application Pool identity has write access

STEP 4: CONFIGURE APPLICATION SETTINGS (OPTIONAL)
--------------------------------------------------
Edit appsettings.json if you need to change:
  - Database connection string (default: "Data Source=app.db")
  - Logging levels
  - Feature flags (EnforceCompanyScope, EnableDirectorRole)

Example appsettings.json:
{
  "ConnectionStrings": {
    "Default": "Data Source=app.db"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  },
  "AllowedHosts": "*",
  "Features": {
    "EnforceCompanyScope": false,
    "EnableDirectorRole": true
  }
}

STEP 5: RUN THE APPLICATION
----------------------------
Choose one of these methods:

METHOD A - Direct Execution (Testing):
  1. Open PowerShell or Command Prompt
  2. Navigate to the folder: cd C:\ShiftManager\ProjectPublish
  3. Run: .\ShiftManager.exe
  4. You should see output like:
     "info: Microsoft.Hosting.Lifetime[14]
      Now listening on: http://localhost:5000"
  5. Open browser: http://localhost:5000

METHOD B - Windows Service (Production - Recommended):
  Using NSSM (Non-Sucking Service Manager):
  1. Download NSSM (on a machine with internet, then transfer)
  2. Run: nssm install ShiftManager
  3. Path: C:\ShiftManager\ProjectPublish\ShiftManager.exe
  4. Set environment variables in the service configuration
  5. Start service: nssm start ShiftManager

  Using sc.exe (Built-in Windows):
  sc create ShiftManager binPath="C:\ShiftManager\ProjectPublish\ShiftManager.exe"
  sc start ShiftManager

METHOD C - IIS (Internet Information Services):
  1. Open IIS Manager
  2. Add Website:
     - Site name: ShiftManager
     - Physical path: C:\ShiftManager\ProjectPublish
     - Binding: Port 80 (or your preferred port)
  3. Application Pool Settings:
     - .NET CLR Version: No Managed Code (self-contained app)
     - Set environment variables in Application Pool → Advanced Settings
  4. Ensure web.config is present (should be auto-generated)

STEP 6: CONFIGURE PORTS & FIREWALL
-----------------------------------
Default ports:
  - HTTP: 5000 (if running directly)
  - HTTPS: 5001 (if configured)

To change the port, edit appsettings.json and add:
{
  "Kestrel": {
    "Endpoints": {
      "Http": {
        "Url": "http://localhost:8080"
      }
    }
  }
}

Firewall configuration:
  netsh advfirewall firewall add rule name="ShiftManager HTTP" dir=in action=allow protocol=TCP localport=5000

STEP 7: VERIFY DEPLOYMENT
--------------------------
1. Check the application is running:
   - Open browser to http://[server-ip]:5000
   - You should see the login page

2. Login with default credentials:
   - Email: admin@local
   - Password: [Your SEED_ADMIN_PASSWORD value]

3. Check database creation:
   - Verify app.db file exists in the application folder
   - Initial size should be around 100-200 KB

4. Check logs:
   - Look for any error messages in the console output
   - If using IIS, check Windows Event Viewer

DATABASE INFORMATION
================================================================================

Database Type: SQLite (file-based, no server required)
Database File: app.db (created automatically on first run)
Location: Same folder as ShiftManager.exe (unless configured otherwise)

The database includes:
  - Companies table (multi-tenant support)
  - Users table (admin, managers, employees, trainees, directors)
  - Shifts table (shift scheduling)
  - ShiftTypes table (morning, noon, night, middle shifts)
  - Configurations table (rest hours, weekly caps)
  - Notifications table
  - Localization: English (en-US) and Hebrew (he-IL)

On first run, the application will:
  1. Create the database file
  2. Run all EF Core migrations
  3. Seed initial company: "Demo Co"
  4. Seed shift types: MORNING, NOON, NIGHT, MIDDLE
  5. Seed config: RestHours=8, WeeklyHoursCap=40
  6. Seed admin user: admin@local (with your password)

BACKUP RECOMMENDATION:
  - Backup the app.db file regularly
  - Simple copy: copy app.db app_backup_YYYYMMDD.db
  - Store backups in a separate location

================================================================================
TROUBLESHOOTING
================================================================================

ISSUE 1: Application won't start - "SEED_ADMIN_PASSWORD must be set"
FULL ERROR MESSAGE:
  "Unhandled exception. System.InvalidOperationException:
   SEED_ADMIN_PASSWORD environment variable must be set in production.
   Set this via environment variables or app configuration."

ROOT CAUSE:
  The application is running in Production mode and requires a password
  for security reasons. It won't start without it.

SOLUTIONS (Choose the easiest one):

  ✓ EASIEST FIX - Edit appsettings.json:
    1. Open C:\ShiftManager\ProjectPublish\appsettings.json in Notepad
    2. Find the line: "SEED_ADMIN_PASSWORD": "",
    3. Change it to: "SEED_ADMIN_PASSWORD": "YourPassword123!",
    4. Save the file
    5. Run ShiftManager.exe again

    This will work immediately - no need to set environment variables!

  ✓ ALTERNATIVE - Use Environment Variable:
    PowerShell:
      $env:SEED_ADMIN_PASSWORD = "YourPassword123!"
      $env:ASPNETCORE_ENVIRONMENT = "Production"
      .\ShiftManager.exe

    Command Prompt:
      set SEED_ADMIN_PASSWORD=YourPassword123!
      set ASPNETCORE_ENVIRONMENT=Production
      ShiftManager.exe

  ✓ TEMPORARY WORKAROUND - Run in Development Mode:
    PowerShell:
      $env:ASPNETCORE_ENVIRONMENT = "Development"
      .\ShiftManager.exe

    NOTE: In Development mode, the default password is "admin123"
          This is NOT recommended for production servers!

ISSUE 2: "Access denied" or "database is locked"
SOLUTION:
  - Ensure the application has write permissions to the folder
  - Close any other applications accessing app.db
  - Check folder permissions (STEP 3)

ISSUE 3: Cannot access the website from other machines
SOLUTION:
  - Configure firewall rules (STEP 6)
  - If running directly, change binding from localhost to 0.0.0.0:
    Use ASPNETCORE_URLS environment variable:
    $env:ASPNETCORE_URLS = "http://0.0.0.0:5000"

ISSUE 4: Database errors on startup
SOLUTION:
  - Delete app.db and restart (will recreate from scratch)
  - Check disk space availability
  - Verify SQLite DLL (e_sqlite3.dll) is present in folder

ISSUE 5: Port already in use
SOLUTION:
  - Check what's using the port: netstat -ano | findstr :5000
  - Change the port in configuration (STEP 6)

ISSUE 6: Missing files or DLLs
SOLUTION:
  - Ensure ALL files from ProjectPublish folder were copied
  - Verify folder structure is intact (wwwroot, Resources, Migrations)

ISSUE 7: Localization not working
SOLUTION:
  - Ensure Resources folder is present with:
    - SharedResources.resx
    - SharedResources.he-IL.resx
  - Ensure he-IL folder is present with localized resource DLLs

================================================================================
SECURITY RECOMMENDATIONS
================================================================================

1. CHANGE DEFAULT PASSWORDS:
   - After first login, change the admin password immediately
   - Use strong passwords (12+ characters, mixed case, numbers, symbols)

2. HTTPS CONFIGURATION:
   - For production, configure HTTPS with a valid certificate
   - Edit appsettings.json to disable HTTP redirection if needed

3. FIREWALL:
   - Only open necessary ports
   - Restrict access to trusted IP ranges if possible

4. DATABASE SECURITY:
   - Protect app.db file with NTFS permissions
   - Regular backups to secure location
   - Consider encrypting backups

5. FILE PERMISSIONS:
   - Application folder: Read & Execute for app user only
   - app.db: Read & Write for app user only
   - Restrict access to appsettings.json (contains connection strings)

6. UPDATES:
   - Plan for periodic application updates
   - Keep Windows Server 2022 patched and updated
