## 3. Critical Conventions (REUSE — Don't Redesign)

### LoggerMessage Source-Gen Patterns (Stable after 8 phases)

Three reuse patterns. Pick the one that fits each file:

#### Pattern A: One method per call site (Phases 1, 2)
Every log call gets a unique partial method. Right when templates are all distinct (Login.cshtml.cs, NotificationService.cs).

#### Pattern B: Method reuse via parameter (Phases 3, 7)
Boilerplate logs that recur across multiple endpoints distinguished only by `Endpoint` (the controller method name) get **one shared method**, called from each endpoint with `nameof(MethodName)`. Used in V1 controllers where 5-6 endpoints share `LogApiEndpointNotEnabled` etc.

```csharp
// One declaration covers 5+ call sites
[LoggerMessage(EventId = 6000, Level = LogLevel.Warning,
    Message = "API endpoint not enabled. Endpoint={Endpoint}, Path={Path}")]
private static partial void LogApiEndpointNotEnabled(ILogger logger, string endpoint, PathString path);

// Call from each endpoint:
LogApiEndpointNotEnabled(_logger, nameof(ListTimeOffRequests), HttpContext.Request.Path);
LogApiEndpointNotEnabled(_logger, nameof(GetTimeOffRequest), HttpContext.Request.Path);
// etc.
```

#### Pattern C: Template parameterization (Phases 4, 5, 8)
Repeated templates that differ only by an action verb get the verb extracted as `{Action}` placeholder. Used in Calendar/Table for `LogErrorAction(ex, "ensuring shift instance")` covering 15 catch sites; Requests/Index for `LogSecurityUnauthorizedAction(ex, ..., "approve", "swap", ...)` covering Cartesian product of action × entity type; **Pages/Admin/Users (Phase 8)** for `LogUnauthorizedUserActionWithGrant` parameterizing the verb across 6 handlers (toggle/role/jobtype/password-reset/unlock/delete).

**Behavioral note**: Pattern C produces *structured-log property* on the action verb instead of embedding it in the literal. Console output is identical; structured-log consumers gain a filterable property. **Strict forward-compatibility, no behavior change.**

#### Pattern C variant: bare-vs-suffixed templates (NEW from Phase 8)
When a literal recurs verbatim with optional suffixes (e.g., 10 sites of bare `"Invalid or missing NameIdentifier claim"` plus 3 with `" during X"` suffix), use one method for the bare form + distinct methods for each suffix variant. **Do not** parameterize the suffix as `{Context}` — produces ugly call-site strings with embedded leading spaces. Distinct methods are cleaner.

### Type Signature Lessons Learned

`[LoggerMessage]` requires concrete signatures. The `params object?[]` overload is gone; if your call site passes a nullable, the partial method MUST take a nullable.

| Source-site value | Correct partial signature |
|---|---|
| `int?` (e.g., `companyId` populated only after recipient lookup) | `int? companyId` not `int companyId` |
| `string?` (raw claim value via `User.FindFirst("CompanyId")?.Value`) | `string? companyId` |
| `int` (parsed from claim) | `int companyId` |
| `PathString` (`HttpContext.Request.Path`) | `PathString path` (requires `using Microsoft.AspNetCore.Http;`) |
| Enum types like `UserRole`, `RequestStatus`, `NotificationType`, `TimeOffType`, `OnDutyType` | Same enum type — all live in `ShiftManager.Models.Support` namespace |
| `Exception` (for `LogError(ex, ...)`) | Place **immediately after `ILogger logger`**: `(ILogger logger, System.Exception ex, ...)` — source-gen detects positionally |

**Two distinct CompanyId types in the same controller**: V1 controllers often have both `int companyId` (parsed success-path value) AND `string? companyId` (raw catch-block claim). Keep them as separate partial methods — *don't* try to coerce one into the other.

**Phase 8 lesson**: In a single PageModel where the same `int? userMolecule` shape appears in just 1-2 sites, don't bother parameterizing. The Phase 8 file used Pattern A heavily despite being 60 sites — many handlers had structurally distinct events.

## 6. Anti-Patterns to Avoid

1. **Don't trust dedup-chain-canonical findings without verification.** ~30% of HiddenBugs lens findings were factually invalid in prior sprints.
2. **Don't add defensive code "just in case."** Invalid findings get verification logged, NOT a null check that compensates for a non-bug. CLAUDE.md §4.
3. **Don't bulk-migrate API call sites without per-site review.** F-C-006 warned about response-shape drift.
4. **Don't fix CA1860 (`.Any()` → `.Count > 0`) with global sed.** Catches `IQueryable<T>` and breaks SQL translation.
5. **Don't squash migrations without deployment-coordination plan.** Air-gapped deployments at unknown migration points.
6. **Don't try multiple LoggerMessage files in one PR.** Per-file PRs are reviewable; bundling defeats the source-gen build implications check.
7. **Don't add `TreatWarningsAsErrors` until Batches K and L Slice 10+ close.** With 2,186 warnings still open, flipping it turns every PR into a build failure. Only enable after warnings are below ~50.
8. **Don't run `dotnet build --no-incremental` during a focused edit cycle** unless you need the warning baseline. It can rewrite `packages.lock.json` as a side-effect.
9. **Don't `taskkill` ShiftManager.exe.** Permission hook blocks it. User terminates manually.
10. **Don't break existing test mocks when changing constructor signatures.** When migrating PageModels to inject new services (like `IBackgroundTaskQueue` instead of `IServiceScopeFactory`), grep `ShiftManager.Tests/` for `new SignupModel(...)`-style constructor calls and update mocks.
11. **Don't try to coerce `int` and `string?` companyId types into one partial method.** V1 controllers genuinely have both — keep distinct signatures.
12. **Don't reuse a partial method's name across classes.** Each LoggerMessage method is class-scoped. EventIds are global.
13. **Don't filter CA1848 counts with bare filename substring**. `"Users.cshtml.cs"` matches `LockedUsers.cshtml.cs` and `GetEligibleUsers.cshtml.cs` too — use `"Admin\\Users.cshtml.cs"` (note escaped backslash for PowerShell regex). This wasted ~5 minutes in Phase 8 verification.
14. **Don't parameterize a suffix when it would embed leading whitespace at call sites.** Phase 8 considered `Message = "Invalid claim{Context}"` for the 13 claim-error variants — call sites would have read `LogInvalidClaim(_logger, " during user creation audit");` which is uglier than 4 distinct method names. Distinct methods chosen.
