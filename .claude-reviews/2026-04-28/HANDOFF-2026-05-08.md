## 3. Critical Conventions (REUSE — Don't Redesign)

### EF Core 9 Capabilities (Verified Empirically)

This project is on **EF Core 9.0.9** (verified `ShiftManager.csproj`). Slice 6 + GriffinService email lookup proved these patterns translate at runtime:

- ✅ `field.Contains(value, StringComparison.OrdinalIgnoreCase)` works in EF queries
- ✅ `field.ToLowerInvariant()` translates to SQL `LOWER()`
- ❌ Do NOT use `string.Equals(StringComparison)` inside an `IQueryable.Where()` — translation depends on provider
- ❌ Do NOT bulk-rewrite `.Any()` → `.Count > 0` (analyzer fires only on `ICollection<T>`, but global sed catches `IQueryable<T>` too — that breaks EF translation)

SQLite `LIKE` is case-insensitive only for ASCII characters by default. For Hebrew, `LIKE 'a%' COLLATE NOCASE` is a no-op — but Hebrew has no case anyway, so this is a semantic equivalence, not a bug.

### Culture Mapping Rule (Settled)

| Context | Culture |
|---|---|
| Audit log values, wire format (CSV/JSON/HTTP), HMAC keys, file timestamps, config storage, feature-flag prefix matching | `CultureInfo.InvariantCulture` |
| Human-localized prose (TempData success/error messages, email body content, UI text) | `CultureInfo.CurrentCulture` |
| Display with explicit format strings (PDF/Excel cells using `yyyy-MM-dd`, `HH:mm`) | **Invariant** — explicit format pins output, server-locale stability dominates |
| ASCII protocol strings (`StartsWith("FF_")`, header names, file extensions, `"http"`, `"he"` BCP-47) | `StringComparison.Ordinal` |
| Case-insensitive search across user-typed input | `StringComparison.OrdinalIgnoreCase` |
| Internal comparison of canonical identifiers | `StringComparison.Ordinal` |
| Interpolated string with multiple components (HMAC keys especially) | `FormattableString.Invariant($"...")` — wraps the entire interpolation |
| StringBuilder with format placeholders | `sb.AppendLine(CultureInfo.InvariantCulture, $"...")` |

## 6. Anti-Patterns to Avoid

1. **Don't trust dedup-chain-canonical findings without verification.** ~30% of HiddenBugs lens findings were factually invalid in prior sprints.
2. **Don't add defensive code "just in case."** Invalid findings get verification logged, NOT a null check that compensates for a non-bug. CLAUDE.md §4.
3. **Don't bulk-migrate API call sites without per-site review.** F-C-006 warned about response-shape drift. Each site has different intent.
4. **Don't fix CA1860 (`.Any()` → `.Count > 0`) with global sed.** Catches `IQueryable<T>` and breaks SQL translation.
5. **Don't squash migrations without deployment-coordination plan.** Air-gapped deployments at unknown migration points.
6. **Don't try all of Batch K (1,720 sites) in one PR.** Source-gen partial classes have build implications; per-file PRs are reviewable.
7. **Don't add `TreatWarningsAsErrors` until Batches K and L Slice 10+ close.** With 2,524 warnings still open, flipping it turns every PR into a build failure. Only enable after warnings are below ~50.
8. **Don't run `dotnet build --no-incremental` during a focused edit cycle** unless you need the warning baseline. It can rewrite `packages.lock.json` as a side-effect — revert with `git checkout -- packages.lock.json` if you didn't intend a lockfile change.
9. **Don't `taskkill` ShiftManager.exe.** Permission hook blocks it. User terminates manually.
