================================================================================
                  AIR-GAPPED DEPLOYMENT GUIDE
                         ShiftManager
================================================================================

This guide explains how to deploy ShiftManager to an air-gapped (offline)
Windows machine that has no internet connection.

================================================================================
                  UNDERSTANDING THE ISSUE
================================================================================

When you copy files via USB to a Windows machine, Windows marks them as
"potentially unsafe" by adding a Zone.Identifier alternate data stream.

This causes the following error when running the application:

  "Could not load file or assembly 'SixLabors.ImageSharp, Version=3.0.0.0'"

This error does NOT mean the DLL file is missing - it means Windows is
BLOCKING the DLL from loading!

================================================================================
                  DEPLOYMENT PROCESS (STEP BY STEP)
================================================================================

STEP 1: BUILD THE DEPLOYMENT PACKAGE (On Development Machine)
--------------------------------------------------------------

On the machine with internet and Visual Studio/.NET SDK:

1. Open PowerShell in the project directory
2. Run the build script:

   .\Build-Release.ps1 -Version "1.0.0"

3. Wait for the build to complete (this may take a few minutes)

4. Locate the deployment package:

   packages\ShiftManager-v1.0.0-win-x64.zip

5. Copy this ZIP file to your USB drive


STEP 2: TRANSFER TO AIR-GAPPED MACHINE
--------------------------------------------------------------

1. Insert USB drive into air-gapped machine

2. Copy the ZIP file from USB to a local folder:

   Example: C:\ShiftManager\

3. RIGHT-CLICK on the ZIP file → Properties

4. Check the "Unblock" checkbox (if present) → Click OK

5. Extract the ZIP file completely to a folder:

   Example: C:\ShiftManager\ProjectPublish\


STEP 3: VERIFY FILES (CRITICAL!)
--------------------------------------------------------------

Before starting the application:

1. Open the extracted folder (ProjectPublish)

2. Double-click: VERIFY_FILES.bat

3. Review the verification results:

   ✅ All files should be present
   ✅ DLL count should be 330-340 files
   ✅ Critical DLLs should be found:
      - SixLabors.ImageSharp.dll
      - ShiftManager.dll
      - e_sqlite3.dll

4. If files are missing:
   → Recopy from USB
   → Check antivirus quarantine
   → Re-extract ZIP file


STEP 4: UNBLOCK FILES (CRITICAL!)
--------------------------------------------------------------

This step prevents the "Could not load file or assembly" error:

1. Double-click: UNBLOCK_FILES.bat

2. Wait for the script to complete (may take 1-2 minutes)

3. Check the results:

   ✅ Should show "Files unblocked using PowerShell"
      OR
   ✅ Should show "Files unblocked using streams.exe"
      OR
   ✅ Should show individual DLLs unblocked

4. If unblocking fails:
   → See "MANUAL UNBLOCK PROCEDURE" below


STEP 5: START THE APPLICATION
--------------------------------------------------------------

1. Double-click: START_HERE.bat

2. The application should start without errors

3. Browser should open to: http://localhost:5000

4. Log in with the admin credentials from appsettings.json


================================================================================
                  MANUAL UNBLOCK PROCEDURE
================================================================================

If UNBLOCK_FILES.bat fails, use one of these methods:

METHOD 1: Using File Properties (Easiest)
------------------------------------------

1. Right-click on the ProjectPublish folder
2. Select "Properties"
3. At the bottom of General tab, check "Unblock"
4. Click "Apply" → select "Apply to all subfolders and files"
5. Click OK

METHOD 2: Using PowerShell (Most Reliable)
------------------------------------------

1. Right-click PowerShell → Run as Administrator
2. Navigate to the folder:

   cd "C:\ShiftManager\ProjectPublish"

3. Run unblock command:

   Get-ChildItem -Recurse | Unblock-File

4. Wait for completion (no output means success)

METHOD 3: Using Command Prompt with PowerShell
----------------------------------------------

If PowerShell execution policy is restricted:

1. Open Command Prompt (cmd.exe)
2. Navigate to the folder:

   cd C:\ShiftManager\ProjectPublish

3. Run this command:

   powershell.exe -ExecutionPolicy Bypass -Command "Get-ChildItem -Recurse | Unblock-File"


================================================================================
                  VERIFICATION OF UNBLOCK
================================================================================

To verify files are unblocked:

1. Open PowerShell in the ProjectPublish folder

2. Run this command:

   Get-Item .\SixLabors.ImageSharp.dll -Stream Zone.Identifier

3. Expected result:

   ✅ "Error: Cannot find path" = File is UNBLOCKED (good!)
   ❌ Zone.Identifier stream found = File is BLOCKED (bad!)


================================================================================
                  TROUBLESHOOTING
================================================================================

ERROR: "Could not load file or assembly 'SixLabors.ImageSharp'"
----------------------------------------------------------------

CAUSE: Files are blocked by Windows

SOLUTION:
1. Close the application (Ctrl+C in the window)
2. Run UNBLOCK_FILES.bat
3. If that fails, use Manual Unblock Procedure (METHOD 2)
4. Restart the application with START_HERE.bat


ERROR: "SixLabors.ImageSharp.dll not found"
--------------------------------------------

CAUSE: File is actually missing or corrupted

SOLUTION:
1. Run VERIFY_FILES.bat to check which files are missing
2. Check file sizes in DLL_CHECKSUMS.txt
3. Recopy entire folder from USB
4. Check antivirus quarantine


ERROR: Application starts but crashes when uploading avatars
-------------------------------------------------------------

CAUSE: SixLabors.ImageSharp.dll is blocked or corrupted

SOLUTION:
1. Close the application
2. Run VERIFY_FILES.bat
3. Compare checksums in DLL_CHECKSUMS.txt using:

   CertUtil -hashfile SixLabors.ImageSharp.dll SHA256

4. If checksum doesn't match, recopy from USB
5. Run UNBLOCK_FILES.bat again


ERROR: Port 5000 is already in use
-----------------------------------

CAUSE: Another application is using port 5000

SOLUTION:
Edit appsettings.json and change the port:

  "Urls": "http://localhost:5001"  (change 5000 to 5001)


================================================================================
                  SECURITY NOTES
================================================================================

Q: Is it safe to unblock these files?

A: YES, if you obtained them from a trusted source. The files are blocked
   because Windows doesn't trust files from external sources (USB, network).

   After you verify:
   - ZIP checksums match (using .sha256 file)
   - DLL checksums match (using DLL_CHECKSUMS.txt)

   It is safe to unblock the files.

Q: Why do I need to unblock DLLs but not EXE files?

A: Windows .NET applications load DLLs dynamically at runtime. Blocked DLLs
   will fail to load with "Could not load file or assembly" errors, even
   though the files physically exist.

================================================================================
                  SUPPORT
================================================================================

If you continue to have issues after following this guide:

1. Run VERIFY_FILES.bat and save the output
2. Check DLL checksums using CertUtil
3. Verify PowerShell is available on the air-gapped machine
4. Check Windows Event Viewer for detailed error messages

Common root causes:
- Files not unblocked (95% of issues)
- Partial/corrupted USB transfer
- Antivirus quarantine
- Missing .NET dependencies (rare with self-contained deployment)
